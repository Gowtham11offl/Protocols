 ### What is I2C?

  I2C stands for Inter-Integrated Circuit (often pronounced "I-squared-C" or "I-two-C").

  Developed by Philips (now NXP), it is a synchronous, multi-device bus designed to connect multiple chips (sensors,
  EEPROMs, OLED displays, real-time clocks) to a microcontroller using only two wires.
  ──────
  ### The Real-World Analogy: A Classroom with One Teacher

  Imagine a classroom:

  1. The Teacher (Controller / Master): Holds a metronome (Clock) and controls the conversation.
  2. The Students (Peripherals / Slaves): Each student has a unique name tag (Address, e.g., "Student #42").
  3. The Shared Air (Two wires):
      • Whenever the teacher wants to talk to someone, they tap the metronome (Clock - SCL) and announce: "I want to
      talk to Student #42, and I want to write instructions to you!"
      • Every student hears the message, but only Student #42 stands up and nods (ACK). All other students stay quiet.
      • The teacher and Student #42 exchange notes, and the conversation ends when the teacher says "Class dismissed"
      (STOP).

  ──────
  ### Physical Connection (The 2-Wire Bus)

  No matter how many sensors or chips you have, you still only need 2 lines:

                      +3.3V / 5V
                          |
                         [R]  [R]  <-- Pull-up Resistors (typically 2.2kΩ to 10kΩ)
                          |    |
            SDA ----------+----+-------------------+------------------
                               |                   |
            SCL ---------------+-------------------+------------------
                               |                   |
                         +-----------+       +-----------+
                         |  Master   |       |  Slave 1  |       |  Slave 2  |
                         |   (MCU)   |       | (Temp Sen)|       |  (OLED)   |
                         |           |       | Addr:0x48 |       | Addr:0x3C |
                         +-----------+       +-----------+       +-----------+

  1. SDA (Serial Data): Transports data bits back and forth between master and slaves (bidirectional).
  2. SCL (Serial Clock): Generated by the Master to synchronize bit transfers (tells everyone when to read the bit).
  3. Pull-up Resistors: Keep both lines pulled to HIGH (1) when nobody is transmitting.
  ──────
  ### Why Pull-Up Resistors? (Open-Drain Explained Simply)

  I2C pins use an open-drain (or open-collector) circuit:

  • Devices can only pull the wire down to Ground (0).
  • No device ever actively drives the line HIGH. When released, the pull-up resistor gently pulls it back to HIGH (1).

  Why do this?
  If two devices tried to talk at once, and one output 5V while the other output 0V, you’d get a short circuit and fry
  the chips. With open-drain, if both pull LOW, it just stays LOW safely without damage. This is called a "Wired-AND"
  connection.
  ──────
  ### Addressing: How Does the Master Pick a Slave?

  Every I2C slave device comes with a 7-bit address (e.g., 0x48 for a temperature sensor, 0x68 for an MPU6050 gyro).

  Since 7 bits allow values from 0 to 127, you can theoretically hang up to 128 devices on the exact same two wires
  without needing extra pins.
  ──────
  ### Anatomy of an I2C Message (Frame)

  A complete transaction follows this exact sequence:

    +-------+--------------------+-----+-----------+-----+-------+
    | START | 7-bit Slave Addr + | ACK | 8-bit     | ACK | STOP  |
    | Cond. | R/W bit (8th bit)  |     | Data Byte |     | Cond. |
    +-------+--------------------+-----+-----------+-----+-------+

  #### 1. START Condition

  Normally, data on SDA only changes when SCL is LOW. The START condition is special:

  • SDA falls from HIGH to LOW while SCL stays HIGH.
  • This alerts every chip on the bus: "A message is starting!"

    SCL:  ~~~~~~~~~\________
    SDA:  ~~~~~~\___________
              ^ START

  #### 2. Address + Read/Write Bit (1 Byte)

  The master transmits 8 bits:

  • Bits 7 to 1: The 7-bit Slave Address.
  • Bit 0 (R/W):
      • 0 = Master wants to Write data to the slave.
      • 1 = Master wants to Read data from the slave.


  #### 3. ACK / NACK (Acknowledge)

  • After every 8 bits sent, the transmitter releases SDA.
  • During the 9th clock pulse, the receiver must pull SDA LOW to say ACK ("Got it!").
  • If the line stays HIGH, it is a NACK ("Nobody home" or "Error").

  #### 4. Data Transfer

  • 8 bits of data sent sequentially (MSB first).
  • Followed by an ACK/NACK bit.
  • Multiple data bytes can be streamed one after another.

  #### 5. STOP Condition

  When the master is finished:

  • SDA rises from LOW to HIGH while SCL stays HIGH.
  • This releases the bus back to the idle state.

    SCL:  ________/~~~~~~~~~
    SDA:  ___________/~~~~~~
                   ^ STOP
  ──────
  ### A Clever Feature: Clock Stretching

  What happens if the master is sending data faster than a slow slave sensor can process it?

  The slave can hold the SCL line LOW with its open-drain pin:

  • The master sees SCL is stuck LOW and pauses.
  • Once the slave finishes its internal processing, it releases SCL.
  • SCL pulls back HIGH, and communication resumes.

  This is called Clock Stretching (hardware flow control).

  To understand why this is such a brilliant design, let's look at what is happening inside the microchips at the
  transistor level.
  ──────
  ### 1. The Normal Way: "Push-Pull" (Totem-Pole)

  Most standard microcontroller pins (like regular GPIOs, SPI pins, or UART TX pins) use what is called a Push-Pull
  stage.

  Inside the chip, each pin has two transistors:

  • An upper switch connected to 5V (Power)
  • A lower switch connected to 0V (Ground)

                 +5V
                  |
               [Upper Switch]  <--- Turn ON to output HIGH (Push 5V out)
                  |
       Pin -------+
                  |
               [Lower Switch]  <--- Turn ON to output LOW (Pull to 0V)
                  |
                 GND (0V)

  #### What happens if you connect two Push-Pull pins to the same wire?

  Suppose Chip A and Chip B are wired together. If both chips transmit at the same time:

  • Chip A tries to send a 1 → turns its Upper Switch ON (connects to 5V).
  • Chip B tries to send a 0 → turns its Lower Switch ON (connects to 0V).

  Now look at the path electricity takes:

        +5V (Chip A)
         |
      [ON] (Upper switch in Chip A)
         |
         +======== THE SHARED WIRE ========+
                                           |
                                         [ON] (Lower switch in Chip B)
                                           |
                                          GND (0V in Chip B)

  Notice what is missing: There is no resistor to limit the current!

  By Ohm's Law (I = V/R):

                  5V
    Current = ────────── = Huge Current (Amperes!)
              almost 0 Ω

  This is a direct short circuit from Power to Ground through the silicon. Within milliseconds, the tiny internal
  wires and transistors overheat and permanently melt (fry). This condition is called Bus Contention.
  ──────
  ### 2. The Solution: "Open-Drain" (No Upper Switch)

  In an Open-Drain pin, engineers simply removed the upper switch entirely.

  There is only one switch (a transistor called an NMOS):

       Pin -------+
                  |
               [Lower Switch (NMOS)]
                  |
                 GND (0V)

  This pin can only do two things:

  1. Drive LOW (0): Turn the lower switch ON. The pin connects to Ground (0V).
  2. Release / Float (1): Turn the lower switch OFF. The pin is completely disconnected (floating, also called high-
  impedance / Hi-Z).

  │ An open-drain pin can never push 5V. It can only connect to Ground or let go.
  ──────
  ### 3. Enter the Pull-Up Resistor

  Because the pin cannot supply 5V, we place a single external Pull-Up Resistor between the bus wire and 5V:

                        +5V
                         |
                        [R]  Pull-up Resistor (e.g., 4.7 kΩ)
                         |
       THE SHARED WIRE --+--------------------------+
                         |                          |
                      [Switch A]                 [Switch B]
                       (Chip A)                   (Chip B)
                         |                          |
                        GND                        GND

  Now let's see what happens in all scenarios:

  #### Scenario 1: Nobody wants to talk (Both release the line)

  • Switch A is OFF, Switch B is OFF.
  • No electricity flows to Ground.
  • The resistor gently "pulls" the wire up to 5V (Logic 1).

  #### Scenario 2: Chip A wants to send a 0

  • Switch A turns ON (connects wire to Ground).
  • The wire drops to 0V (Logic 0).
  • Does current short-circuit? No! Current flows from 5V through the resistor:

           5V
    I = ──────── ≈ 0.001 A (1 mA)
        4, 700 Ω

  1 mA is completely harmless.

  #### Scenario 3: BOTH Chip A and Chip B pull LOW at the same time

  • Switch A is ON, Switch B is ON.
  • Both are connecting the wire to Ground.
  • 0V connected to 0V causes zero conflict, zero heat, and zero damage. The line just stays at 0V safely!
  ──────
  ### 4. Why is it called "Wired-AND"?

  In digital electronics, an AND gate outputs 1 only if all inputs are 1.

  Look at what happens to the voltage on the shared wire depending on what each chip does:

     Chip A wants:   │   Chip B wants:   │   Transistor A    │   Transistor B   │   Wire Voltage   │   Logic Result
  ───────────────────┼───────────────────┼───────────────────┼──────────────────┼──────────────────┼──────────────────
     0 (Pulls LOW)   │   0 (Pulls LOW)   │     ON (GND)      │     ON (GND)     │        0V        │        0
     0 (Pulls LOW)   │   1 (Releases)    │     ON (GND)      │   OFF (Float)    │        0V        │        0
     1 (Releases)    │   0 (Pulls LOW)   │    OFF (Float)    │     ON (GND)     │        0V        │        0
     1 (Releases)    │   1 (Releases)    │    OFF (Float)    │   OFF (Float)    │  5V (Pulled up)  │        1

  The wire output is:

    Bus Value = A AND B

  Without buying or soldering any logic gate chip, the physical wire itself acts as an AND gate. That's why it is
  called Wired-AND.
  ──────
  ### Why is this essential for I2C?

  This elegant trick enables three features of I2C:

  1. Safe Acknowledge (ACK): The Master sends data, releases the line, and the Slave safely pulls it LOW to say "I got
  it" without any collision.
  2. Clock Stretching: A slow slave can grab the SCL clock wire and hold it LOW to tell the Master: "Wait for me, I'm
  busy!"
  3. Multi-Master Arbitration (No Crashes): If two Masters try to transmit at the same millisecond, they both listen
  to the bus while sending. The first one to send a 1 (releases line) while the other sends a 0 (pulls LOW) sees that
  the bus stayed 0. It realizes: "Someone else is talking," backs off gracefully, and tries again later—with zero
  hardware damage.

### PART 1: The 4 Hardware Concepts for RTL Design

1. Open-Drain Modeling in Verilog:
   - To drive '0' (LOW): output 1'b0
   - To drive '1' (HIGH): output 1'bz (release the line; external pull-up resistor pulls it to 1)
   - Code pattern:
       assign scl = (scl_out == 1'b0) ? 1'b0 : 1'bz;
       assign sda = (sda_out == 1'b0) ? 1'b0 : 1'bz;
       assign sda_in = sda;

2. The Golden Rule of I2C Data Timing:
   - Data on SDA can ONLY change when SCL is LOW.
   - Data on SDA must be rock-solid and stable when SCL is HIGH.
   - The ONLY exceptions are START and STOP:
     • START: SDA falls from HIGH to LOW while SCL is HIGH.
     • STOP:  SDA rises from LOW to HIGH while SCL is HIGH.

3. SCL Clock Generation via Enable Ticks:
   - Do NOT use a clock divider to clock flip-flops (avoids clock-domain crossing / skew).
   - Keep the whole circuit running on the fast system clock (e.g., 50 MHz).
   - Divide each SCL bit period into 4 equal quarter-phases using an enable tick.

4. Metastability (2-Stage Synchronizer):
   - External SDA/SCL lines from other chips are asynchronous to the FPGA clock.
   - Synchronize external pins through 2 flip-flops before sampling in the FSM.

> Generating the SCL Clock (Quarter-Phase Ticks) - Why 4 phases?

### Deep Dive: Why an I2C Bit is Divided into 4 Phases

If you only use 2 phases (SCL LOW and SCL HIGH), two critical problems occur:
1. Race Conditions on Edges:
   If you change SDA right when SCL falls, wire delays could cause SDA to change
   a fraction of a nanosecond before SCL drops while SCL is still HIGH.
   This falsely triggers an accidental START or STOP condition!
2. RC Rise-Time Delay:
   Because I2C uses pull-up resistors and has bus capacitance (C_bus), when a line
   is released it charges slowly via an exponential RC curve (t_r = 100ns to 1000ns).
   If you sample the exact moment SCL goes HIGH, the voltage may still be below V_IH,
   reading corrupted data.

The 4-Phase Solution:
  Phase 0 (SCL is LOW):
    - Safe time to change SDA.
    - SCL is guaranteed 0V, so accidental START/STOP is physically impossible.
    - Provides maximum Data Setup Time (t_SU:DAT).

  Phase 1 (SCL rises HIGH):
    - Wait & Settle phase.
    - Gives the pull-up resistor time to charge bus capacitance to a valid HIGH.

  Phase 2 (SCL is HIGH):
    - Dead-center of the clock pulse.
    - Peak stability point. Safest place to sample SDA (incoming data bit or ACK/NACK).

  Phase 3 (SCL falls LOW):
    - Closes the clock window.
    - Data on SDA remained stable through Phase 1, Phase 2, and Phase 3,
      guaranteeing massive Data Hold Time (t_HD:DAT).

Trivial START and STOP Generation with 4 Phases:
  • START: In Phase 0 & 1, SCL=1, SDA=1. In Phase 2, pull SDA=0. In Phase 3, SCL=0.
  • STOP:  In Phase 0 & 1, SCL=1, SDA=0. In Phase 2, release SDA=1.

> Step-by-Step Implementation Guide & Coding Notes

### Step 1: Module Interface & Port Sizing
  - System Clock: clk, reset_n (active-low asynchronous reset)
  - Parameters:
      parameter CLK_FREQ = 50_000_000;
      parameter I2C_FREQ = 100_000;
  - Addressing:
      addr is 7 bits ([6:0]), NOT 8 bits!
      The 8th bit on the bus is the rw bit (0=Write, 1=Read).
      Combined on the bus as: {addr[6:0], rw}
  - Data Width:
      write_data is 8 bits ([7:0])
      read_data is 8 bits ([7:0])
  - Bus Ports:
      inout wire sda;
      inout wire scl;

### Step 2: 4-Phase Tick Math
  - Quarter period calculation:
      localparam QUARTER_PERIOD = CLK_FREQ / (I2C_FREQ * 4); // e.g. 125 ticks
      localparam CNT_WIDTH      = $clog2(QUARTER_PERIOD);    // e.g. 7 bits ([6:0])
  - Trap to Avoid:
      Writing [QUARTER_PERIOD-1 : 0] clk_cnt creates a 125-bit register!
      Always use $clog2(QUARTER_PERIOD) to get the required bit width.

### Step 3: Open-Drain Tri-State Logic
  - Driving the bus:
      assign scl = (scl_out == 1'b0) ? 1'b0 : 1'bz;
      assign sda = (sda_out == 1'b0) ? 1'b0 : 1'bz;
      assign sda_in = sda;

### Step 4: FSM States & Registers
  - States (9 total):
      IDLE, START, ADDR, ACK_ADDR, WRITE_DATA, ACK_DATA, READ_DATA, SEND_ACK, STOP
  - Helper Registers:
      reg [3:0] state;
      reg [7:0] tx_shift; // holds byte being shifted out (MSB first)
      reg [7:0] rx_shift; // collects incoming bits
      reg [2:0] bit_cnt;  // counts 7 down to 0
      reg       rw_reg;   // latches rw mode

### Step 5: Common Verilog Gotchas Encountered
  - Multiple statements under if/else:
      In Verilog, if/else without 'begin ... end' only binds to the FIRST statement.
      Always enclose multiple assignments in:
        if (condition) begin
            statement1;
            statement2;
        end
  - SCL Direction:
      Master must drive SCL; it cannot be declared as an 'input wire'.
      Declared as 'inout wire scl' to support open-drain / clock stretching.
